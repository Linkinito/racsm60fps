# Findings — live session 2026-09-30

First session where global strategies were tested in game with the owner and
targeted corrections were built. Evidence labels follow
[methodology/EVIDENCE_LEVELS.md](methodology/EVIDENCE_LEVELS.md): "owner-observed"
means the owner compared arms visually in play; nothing here is a measured parity
verdict yet. Module: LEVEL_01 (Pokitaru), UCES00420.

## 1. Where the 2x comes from

C1 (three words: second VBlank wait removed, shared delta 1/30 -> 1/60, player
substep limit 2 -> 1) already corrects Ratchet and everything the engine drives
with the frame delta, notably the **animation system** (animation time += delta,
events fire when `event.time < anim.time`, `0x76AA4`).

What stays 2x is **fixed per-call work**, mostly inside the per-entity update
callbacks run by *group pump 1* (`0x1517C` calls `0x6B7F4` at `0x15230`; per-entity
`jalr` at `0x6B9B8`, `a0` = entity, `f12` = delta), plus the particle animators.

## 2. Global approaches tested and rejected

| Arm | Idea | Owner-observed result |
|---|---|---|
| D1 | C1 + 54 legacy one-pass wrapper sites | no visible difference from C1 |
| G1 | run pump 1 every second update with accumulated delta | speeds mostly right, strong judder, Blaster slower |
| G / GI | per-entity half rate, optional half-way position blend | interactions broken, sea flicker, boat platform bug, judder |
| F1 | C1 + all 107 other `1/30` immediates -> `1/60` | almost no change (teleporter animation only) |
| H | halve every float that an entity update changed | partial (butterflies, enemy death); crabs, waterfall still 2x |
| I | apply integer +-1 changes every second update | no fix; Gadgetron shop animation restarts |

Conclusion: stay at 60 Hz everywhere and correct fixed steps where they are
applied, preferably in **shared helpers**, otherwise per class.

## 3. Working targeted corrections (experimental, `tools/runtime/fixes.py`)

| Fix | Mechanism | Scope | Result |
|---|---|---|---|
| `nav` | ground-navigation move `0x2A8F0` adds `direction * speed-per-call` (`pos += disp` at `0x2AA5C`); a halved copy of the displacement is passed | Crab, TMRobotHeadB/TorsoB, TrainingBot | crab speed correct |
| `crab` | crab attack: frame counter `+1` per update compared to constant `27.0` (data RVA `0x2CF3C8`, single reference `0x1254F8`); set to `54.0` | Crab | attack timing correct, damage unchanged |
| `debris` | shrapnel physics `0x191D7C` (life, gravity, `pos += vel` per call) half-step | 8 shrapnel classes | runs; crate debris do not use it |
| `animdisp` | animated displacement `0x6C318` (38 call sites) | 23 classes | **parked**: freezes the game (callers rely on a non-standard register convention) |
| `particles` | per-particle half-step after the waterfall animator `0xDE23C` | waterfall mist/splashes | IG-v8/v9 flickered; cause found (swap-remove of dead particles); IG-v10 pending test |

Player health: player structure at data-segment base + `0x5A838` (module + `0x337940`),
health `f32` at `+0x964`, max at `+0x968`; health written at `0x38700`.

## 4. Particle system

Ablation (temporarily replacing a call by `nop`, `tools/runtime/call-toggle.py`)
identified the main-update call `0x15348 -> 0x8CC18` as the particle system:
waterfall waves, mist and splashes vanish while it is disabled and burst back
afterwards (emitters keep queueing). Update and vertex generation happen in the
same pass, so particles cannot be run at half rate without flicker.

The walker calls one animator per pool through `jalr t0` at `0x8CE54` (standard
ABI). Near the waterfall three animators are active: `0x7E810`, `0xDE23C`
(waterfall; per call: life/age `+= -1.0`, `vel.y -= gravity`, `pos += vel`, drag,
fixed rotation) and `0xDE8A8`. Dead particles are removed by copying the last
80-byte record into their slot (`0xDE458`), so slot identity is not stable.

## 5. Static knowledge extracted

- **Class registration table** (`research/scripts/class-table.py`): 150 LEVEL_01
  classes with their update callbacks (150/150 agree with the earlier atlas) and,
  for 67, an embedded field-definition string with the original field names.
- Engine source paths are embedded (`Code/EFFECTS/*.cpp`, `ENGINE/rendereffect.cpp`).
- Shared-helper census: 37 helpers used by at least 5 classes that store positions
  or do float read-modify-write (`research/scripts/shared-helper-census.py`).

## 6. Lessons for tooling

- A C wrapper replacing a direct `jal` can break callers that assume a callee
  preserves registers it does not use; pointer calls (`jalr`) are safe.
- A PSP plugin `main()` must exit its thread, not return (newlib `exit()` ends the game).
- More than two resident plugins crashed Pokitaru loading (memory pressure, INFERRED).
