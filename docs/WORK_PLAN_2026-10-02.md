# Work plan — understand, identify, patch (2026-10-02)

Scope: Priority 0 only (UCES00420 A=original30 -> C=faithful60). Evidence levels per
docs/methodology/EVIDENCE_LEVELS.md. Domain map: docs/WHY_60FPS_IS_HARD.md.
Fix list: docs/FIX_CATALOGUE_2026-10-01.md.

## Diagnosis of the current method

- The domain model (8 time domains) is sound; the workflow is not. Mechanisms are
  found reactively (owner notices a 2x effect -> live bisection with breakpoints).
  Live debugging is expensive (PPSSPP grew to ~14 GB) and owner impressions are not
  parity measurements.
- The decompilation corpus (5045/5045 functions) already produced most accepted
  fixes: `frametimers` (1/30 constant classification), `camera` caps, `frames30`
  (HUD), `springs` (engine spring 0xE290 refit), `nav` (displacement integrators),
  `crabtimers` (reviewed after the audit), `clock`, `physstep` target 0x2832C,
  `camfilters`. It was used as a **per-function pattern scanner**, not as a model
  of the program.
- The recurring failure is missing **call context**: a function's timing domain
  depends on who calls it and how often. Examples: Blaster_Update was classified
  "delta-based, correct under C1", but it runs inside the player substep loop, so
  C1 halves it (measured A0 4.2 vs C1 2.0 shots/s); the five "HUD fade" phase
  labels were wrong; 10 of 29 generated Crab sites were not timers (no def-use check).

## Principle

Offline first: every live test should falsify a written prediction made from
static analysis, not search blindly. Live sessions stay short, clean-boot,
telemetry-based, with an A0 baseline.

## Offline workstream (no emulator)

O1. **Call-context map** (`level01-call-contexts.json`). Build the caller graph from
    `_local/20261001-mass/all/index.json` (direct callees) + class registration table
    (`level01-class-updates.json`, pump-1 updates) + vtable/slot tables + function
    pointers stored as data; later complete it with indirect edges recorded live
    (`call-probe.py`). Tag each function with its reaching contexts: per-frame main
    loop, player substep loop (body around 0x2FCE8..0x2FCF8), entity update pump,
    particle animator/callback, draw path, init/spawn-only. Domain = function x context.
O2. **Delta dataflow.** Propagate the frame delta from its source through argument
    registers (f12) and stores. Output: functions that receive dt, those that mutate
    persistent state per call without dt (domains 2/3/5 candidates), and dt consumers
    reached through the substep loop (domain 8). Re-check all earlier "already correct
    under C1" verdicts against O1.
O3. **Blaster / weapons offline answer.** Read Blaster_Update, P_Player_WeaponUpdate
    (0x1F2D0), 0x39B74, player timers 0x32588 (+0xA00..0xA18): what actually gates a
    shot (cooldown, animation event, input edge, substep count)? Write the predicted
    effect of `substepdt` and the Ryno behaviour BEFORE the live test.
O4. **Particle callbacks.** List function addresses written into particle records
    (+0 of 0x7E810 records and similar) by spawners; classify each callback body by
    domain; design per-callback fixes instead of generic float halving (rejected
    `particles-all` corrupted packed colours).
O5. **Generator hardening.** For every generated site, extract field def-use (writer,
    readers, comparisons, calls it flows into). Reject sites that feed animation IDs,
    flags or capacities. Apply to TrainingBot before any activation.
O6. **Mechanism ledger** (`research/v2/mechanism-ledger.json`, generated). Merge all
    candidate lists (fixed-step, frame timers, 1/30, clock, springs, displacement,
    particles, phase steps) into one row per mechanism: domain, context, fix, metric,
    A0 value, C value, status (accepted / rejected / untested / not visible). Use it
    to choose live tests by player visibility and to show what remains.
O7. **EBOOT.** Same pipeline on the EBOOT for engine-side time (texture/UV scroll,
    waterfall water scroll, loading screens). Use the PPSSPP GE debugger once to name
    the changing UV/texture-matrix value, then find its writer statically.
O8. **Portability (later).** Hash/compare LEVEL_01 functions against other level
    modules to know which fixes are shared code; plan signature-based patching
    instead of fixed offsets.

Budget rule (AGENTS.md): at most one substantial tooling detour per experiment.
Order: O1+O2 (one tool), then O3, O5, O4, O6; O7/O8 after Pokitaru is mostly closed.

## Live workstream (short sessions)

L1. Restart PPSSPP. On A0, read f12 at both substep iterations (confirm full 1/30 each).
    Test `substepdt` with the ammo meter (Blaster, Ryno, Tremblator) against the O3
    prediction.
L2. A0/C1 **rate-diff telemetry**: sample an entity struct (weapon, player, pool) per
    game second in A0 and C1; report fields whose rate differs by ~2x. Replaces
    breakpoint bisection.
L3. Pending tests: `physstep`, `particles-rate` (IG-v19 installed), `camfilters`,
    `helphint`, Ryno `rynorate`.
L4. Combined candidate C (all accepted fixes) measured on fixed scenarios; promote to
    patches/validated/ only with reproducibility, causal understanding, regression
    checks and environment recorded.
